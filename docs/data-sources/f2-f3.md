# Data Source Research — Formula 2 & Formula 3

**Series IDs:** `f2`, `f3`
**Status:** `integrated`
**Integration path:** `seed`
**Last reviewed:** 2026-09-05

---

## Series Overview

FIA Formula 2 and Formula 3 are the two main feeder series to Formula 1. Both support series race at the same venues as F1 during F1 race weekends (with a few exceptions). ~14 rounds per season for F2, ~10 for F3. F2 weekend: Practice, Qualifying, Sprint Race (Saturday), Feature Race (Sunday). F3 weekend: Practice, Qualifying, Race 1 (Saturday), Race 2 (Sunday).

---

## APIs & Sources Researched

No dedicated public JSON API exists for either series, but a usable structured source does:

**`fiaformula3.com` per-round pages embed schema.org JSON-LD with explicit UTC (`Z`) session timestamps in the raw HTML** — e.g. `https://www.fiaformula3.com/en/racing/2026/monza`. This is how the 2026 F3 times were corrected; parse the JSON-LD rather than the rendered page. Validate any such source against a round you have already verified by hand before trusting it for the rest.

### Sources checked and rejected

| Source | Verdict |
| --- | --- |
| `sportstimes/f1` (powers f2calendar.com / f3calendar.com) | **Do not use.** Checked against raw bytes: places the 2026 F3 Monza sprint at `14:45Z` when the official time is `07:30Z` — a 7h15m error. Wrong on F2 too. |
| `api.fia.com/events/...` | HTML, not JSON. Event-level date ranges only, no session times. |
| `fiaformula2.com/Calendar`, `fiaformula3.com/Calendar` | Round list and date ranges only — authoritative for **calendar structure**, no session times. |

### Authoritative fallback

The official **per-Grand-Prix full weekend timetable on formula1.com** lists every support-series session with the venue's UTC offset stated. Use it when JSON-LD is unavailable, and corroborate with a second independent source (Sky Sports publishes the same schedule in UK time; Wikipedia's per-round articles carry post-event times). Where formula1.com disagreed with two agreeing independent sources, the two-source value was taken.

### Observation: F1 calendar as proxy

Since F2 and F3 race at F1 venues, the F1 calendar (Jolpica API) gives the venue and weekend dates. Session times differ from F1 and would need to be added manually, but circuits and dates can be derived.

**Status:** Not currently implemented — seed files used instead as it's simpler.

## Decision

**Chosen source:** Manual seed files
**Integration path:** Seed (`data/seed/f2.json`, `data/seed/f3.json`)

**Rationale:**
No free public APIs found. Both series co-locate with F1, so schedules are predictable and announced alongside the F1 calendar. ~14 rounds per season — manual curation is low cost. F1 calendar could theoretically be used as a base for circuit/date data, but the complexity of syncing isn't worth it given the small number of rounds.

**Trade-offs accepted:**
- Manual update required each season
- A few non-F1-weekend rounds (F3 has some standalone rounds in some seasons) must be manually tracked

> **Session times must be verified, never approximated.** An earlier version of this
> document accepted "approximate" times based on standard slot patterns. That produced
> calendars where consecutive rounds carried byte-identical times — the 2026 F3 Madrid
> qualifying was 5h25m out and the Melbourne feature race was on the wrong day. Every
> stored time must come from a published timetable, and a round that cannot be verified
> keeps its old value and is recorded as unverified rather than being filled in with a
> plausible guess.

## Data Mapping

Seed files are written directly in silver schema. Key notes:
- `seriesId`: `"f2"` or `"f3"` (not `"formula2"` etc.)
- Session types for **both** F2 and F3: `"Practice"`, `"Qualifying"`, `"Sprint Race"`, `"Feature Race"` — matching the official timetable naming. (This document previously claimed F3 used `"Race 1"`/`"Race 2"`; it does not, and never matched the seed files.)
- Times are stored in **UTC with a trailing `Z`**. Published timetables are in venue-local time, so DST at that date and venue must be applied — this is the single most common source of error. `dateStart`/`dateEnd` must equal the earliest/latest session date **in UTC**, which can differ from the locally-advertised event dates (Melbourne practice at 08:50 AEDT is the previous day in UTC).
- F3 qualifying is sometimes split into Group A / Group B; the seed stores one `Qualifying` entry, so use the first group's start.
- Circuits are identical to F1 — reuse the same `circuit` objects where possible
- `countryCode` must match F1 for the same venue (both must use alpha-2)

## Future Option: Derive from F1 calendar

If this becomes hard to maintain, an alternative approach:
1. After running the F1 fetcher, generate F2/F3 seed events from the F1 silver data
2. Strip F1-specific sessions, add standard F2/F3 session slots at known offsets
3. This would make F2/F3 automatically follow F1 calendar changes

Not implemented yet — seed files are simpler for now.

---

## Maintenance

- **Update frequency:** Once per season (announced alongside F1 calendar), then again per round as timetables are published — late-season rounds are often "time to be confirmed" when the calendar is announced.
- **Season rollover:** Manually update `data/seed/f2.json` and `data/seed/f3.json`
- **Owner:** Manual — check `fiaformula2.com` and `fiaformula3.com` for official calendars
- **Guard:** `pipeline/validate.py` runs cross-round checks on seed files — round contiguity and duplicates (hard errors), and a warning when rounds share identical session times. That warning is a *smell, not proof*: standardised support-race slots repeat legitimately, so it flags rounds worth re-checking rather than failing the build.
